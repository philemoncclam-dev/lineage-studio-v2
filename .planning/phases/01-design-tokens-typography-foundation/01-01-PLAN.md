<assumption_delta_decision>
The advisory assumption-delta detector fired on this phase (`kind: pluralization`).
Reading it in this phase's actual terms, two identity models lose their plurality here:

- **Theme identity.** Today three mechanisms define the same tokens: a
  `prefers-color-scheme` media query and two separate attribute-selector blocks. The
  primary noun becomes **the `data-theme` attribute on the document element**.
- **Font identity.** Today the primary family is a four-entry OS-dependent list whose
  real winner on Windows was never chosen deliberately. The primary noun becomes **the
  single self-hosted `--font-sans` family**, with generic families demoted to a genuine
  last-resort fallback.

**Decision: `promote` (both).** The generalized representation is promoted to primary and
the old specific one is demoted to a detail of one variant — the OS preference becomes an
*input* to the single `data-theme`/`color-scheme` mechanism rather than a second
authority, and the system stack becomes a fallback rather than a delivery mechanism.
Explicitly **not** `add-alongside`: keeping either old mechanism next to the new one is
the exact debt this phase exists to remove.

**Invariant test (accepted, wired in plan 01-02):** `frontend/scripts/audit-tokens.mjs`
asserts that every token has exactly one definition site. It goes red the instant a
future phase reintroduces a second definition block for an already-defined token.
</assumption_delta_decision>

<flagged_assumptions>
Surfaced, not silently resolved. Each needs a human read before or during execution.

1. **Preload strategy deviates from UI-SPEC Font Loading Strategy step 3.** The spec's
   preload href points into `node_modules/`, which resolves in Vite dev but 404s in a
   production build — a broken preload silently reintroduces the FOIT that DS-06 forbids.
   This plan vendors both woff2 files into `frontend/public/fonts/` and hand-authors the
   `@font-face` blocks so the preload href and the font src are byte-identical URLs in
   both dev and prod. Spec step 8 ("no custom subsetting beyond Fontsource's default
   latin subset") is still honoured — the vendored files are Fontsource's own latin
   variable files, unmodified. **If the developer prefers strict spec fidelity, the
   alternative is to keep the Fontsource CSS import and drop the HTML preload entirely,
   accepting a slightly wider swap window.**
2. **The UI-SPEC's retired-size grep list is incomplete against the real codebase.** It
   names 10.5 / 11.5 / 12.5 / 13 / 14 / 17px. The codebase actually declares thirteen
   distinct font sizes: 8.5, 9.5, 10, 10.5, 11, 11.5, 12, 12.5, 13, 14, 15, 17, 18px.
   The unnamed five (8.5, 9.5, 10, 12, 15) are mapped in this plan's task 2 from the
   spec's own *usage* column rather than its grep list. Note that 12px → 13px is a
   visible size *increase* across roughly fourteen declarations.
3. **The UI-SPEC's retired-weight grep list is incomplete.** It names 560 and 620. The
   codebase also declares 500 and 520 (canvas font strings), 640, 650 and 700. The
   "exactly two weights" rule collapses all of them onto 400/600, which visibly
   de-emphasises the uppercase section labels currently at 700.
4. **`--grid` and `--workspace` have no destination in the approved spec.** `--grid` is
   the dot-grid canvas background; `--workspace` is the fallback domain colour returned
   by `colorFor` in `frontend/src/model.tsx` for any layer that is not bronze/silver/gold.
   Plan 01-02 introduces `--color-grid-dot` and `--color-domain-neutral` as new tier-2
   semantics that reference existing primitives (no new hue is introduced, so no new
   collision risk).
5. **`#d9534f` in the error source-chip is a raw hex not on the spec's retired list.**
   It maps to `--color-destructive`.
6. **Ten of the nineteen fallback edge probes are `unclassified` and stay `unresolved`.**
   They are listed at the end of this plan; they are not authored as truths and are not
   dropped.
</flagged_assumptions>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry → local build | Four new third-party packages enter the build graph and their code runs at build time |

| OS colour preference → app theme state | An out-of-app signal influences which token values render |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|

Versions are pinned and `package-lock.json` is committed. This gate is never auto-approvable. |
| T-01-01 | Information disclosure | Font asset origin | medium | mitigate | Fonts are self-hosted from the app's own origin (`/fonts/`). No third-party font CDN link is introduced, so no visitor IP or referrer is disclosed to a font host. Acceptance criteria assert zero external font origins in index.html. |
| T-01-02 | Denial of service | Broken preload href | medium | mitigate | A preload pointing into `node_modules/` 404s in production, wasting a request and silently reintroducing FOIT.

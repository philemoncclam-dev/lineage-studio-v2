<objective>
Migrate every component stylesheet onto the new token layer and retire `App.css` — the
last file holding a competing token base. Introduce the tier-3 component token vocabulary,
collapse thirteen font sizes onto four and seven weights onto two, put every spacing and
radius value on the systematic scale, and remove the last raw colour literals from the CSS.

Purpose: DS-02 is not satisfied by a good token file sitting next to a second, competing
one. Until `App.css`'s `:root` block is gone, the app has two token systems and the phase's
core claim is false. This is also the plan that guards SHELL-07 for the next phase: it
leaves the app fully styled on the new tokens rather than half-migrated.

Output: `frontend/src/styles/components.css`, four rewritten view stylesheets, and a
deleted `App.css`.
</objective>

**Font-size retirement.** The UI-SPEC's mapping table covers six values; the codebase
declares thirteen. All thirteen have a destination:

| Old | Destination | How the original distinction survives |
|---|---|---|
| 8.5 | `--text-micro` (11px) | PK/verified pill text — spec lists this usage under micro |
| 9.5 | `--text-micro` | Uppercase micro labels and mono badges — spec lists badges under micro |
| 10 | `--text-micro` | Column type annotations, keyboard hints — spec lists these under micro |
| 10.5 | `--text-micro` | Spec-mapped; same job, same tier |
| 11 | `--text-micro` | Already the token value |
| 11.5 | `--text-micro` + `--color-text-secondary` | Softer emphasis now carried by colour tier |
| 12 | `--text-base` (13px) | A visible size increase across ~14 declarations — see flagged note below |
| 12.5 | `--text-micro` + `--color-text-tertiary` for the quietest instances | Colour tier carries the quieter-than-body job |
| 13 | `--text-base` | Unchanged |
| 14 | `--text-base` at weight 600 | Weight substitutes for the old size difference |
| 15 (table-detail name) | `--text-base` at weight 600 | Same substitution |
| 15 / 18 (close and clear glyphs) | `--text-heading` (18px) | Icon-button glyph, not body type |
| 17 | `--text-heading` | Rounds up to the nearest surviving step |

**Weight retirement.** Exactly two weights survive. Everything currently at 560, 620,
640, 650 or 700 becomes 600. Everything else becomes 400. The 500 and 520 canvas weights
are handled by plan 01-03, not here.

**Radius and spacing.** Radii: the two badge radii and the 5px input radius become
`--radius-input`; 6px becomes `--radius-card`; 7px, 8px and 9px become `--radius-control`;
10px, 12px and 14px become `--radius-card`; 999px becomes `--radius-pill`; percentage
radii used to draw circles stay as they are. Spacing: round every padding, margin and gap
to the nearest step on the 4px scale, and on an exact tie round DOWN — this app's density
is explicitly dense, and rounding up would inflate the whole layout.
</migration_reference>

<flagged_note>
The 12px → 13px move is the only change in this plan that is visibly larger rather than
smaller, and it touches roughly fourteen declarations (column rows, flow items, transform
prose, breadcrumbs, table-detail rows, definition rows). It follows directly from the
approved four-step ramp, which has no step between micro and base. Surfacing it because
it is a real density change the developer should see on first run, not a silent side
effect. If it reads as too loose, the correction is a `--row-height` adjustment, not a
fifth font size.
</flagged_note>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| token layer → component stylesheets | Every rendered surface takes its colour and geometry from an upstream file it does not control |
| retired stylesheet deletion → running app | Removing a file that currently supplies the entire visual base can leave surfaces unstyled |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-16 | Denial of service | Dangling token reference after the retired stylesheet is deleted | high | mitigate | A `var()` pointing at a token that no longer exists resolves to nothing — text can render invisible or a control can lose its background entirely, with no build error and no runtime error. Mitigated by an acceptance criterion that resolves every `var()` reference in every stylesheet against the union of declared tokens and fails on any miss, plus a human render check across the toolbar, palette, write panel and import overlay. |
| T-01-17 | Spoofing | A domain colour standing in for a UI state | medium | mitigate | Reusing a data-domain hue as a warning or error affordance makes state indistinguishable from data classification, which is the class of confusion THEME-05 exists to close. Mitigated by routing every warning and error surface to the destructive token and asserting zero domain-token references in the two write-flow stylesheets. |
| T-01-18 | Tampering | Colour literal reintroduced into component CSS | medium | mitigate | A single hard-coded hex bypasses both themes and every audit. Mitigated by an acceptance criterion asserting zero hex and zero device-space colour functions across all five stylesheets. |
| T-01-19 | Information disclosure | Overlay scrim opacity too low to obscure content behind a modal | low | accept | The scrim is a visual affordance, not a security control; anything behind it remains in the DOM regardless of opacity. No sensitive content is gated by the scrim in this app. |
| T-01-20 | Elevation of privilege | Component CSS overriding a token value | low | mitigate | Tier-3 tokens are constrained to reference tier-2 semantics only, asserted by a criterion that rejects any tier-3 declaration containing a theme-switching call, so a component cannot silently redefine a theme value. |
</threat_model>

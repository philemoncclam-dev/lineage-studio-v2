<objective>
Fix two real-data correctness defects (WR-03, WR-04) that do not surface on the bundled sample graph but silently corrupt behavior on real Fabric metadata. These are the two `⚠ Warning` items 02-REVIEW.md and 02-VERIFICATION.md flagged as real (not the Phase-3/4-owned WR-02/WR-05, nor the deferred WR-06).

- WR-03 (`frontend/src/model/ids.ts`): `tid`/`nid` sanitize by naive character substitution (`replace(/[^\w-]/g, '_')`), so two distinct raw ids collapse to the same short id — e.g. `table.raw.orders` and `table.raw_orders` both become `raw_orders`. That short id is the key for `tableById`/`byId` Maps (silent merge of unrelated tables), column-edge keys, and literal DOM element ids (`id="ls-${t.id}"`, `querySelector('#ls-'+s)`) — a collision mis-renders lineage and produces duplicate DOM ids.
- WR-04 (`frontend/src/shell/search.ts`): `notebookIndex()` dedupes by display name (dropping same-named notebooks from different workspaces) and its fallback id-resolution branch (`n.label in m.notebookCode ? n.label : n.id`) is unreachable/broken — `m.notebookCode` is keyed by `nid()`-mapped ids, never by label, so it always falls through to `n.id`, which for a graph `GNode` is the RAW id (e.g. `notebook.clean_orders`), inconsistent with the `nid()`-mapped id (`nb_clean_orders`) used everywhere else in `AppModel`. Selecting such a result no-ops or shows "unknown".

Purpose: Make lineage rendering and command-palette notebook search correct on real Fabric data, not just the punctuation-free sample fixture.
Output: A collision-free id derivation with a guard test, and an id-based notebook index consistent with the rest of the model, with coverage.

The `LineageGraph` contract shape is unchanged (CLAUDE.md convention). Only internal short-id derivation and the palette's search index change.
</objective>

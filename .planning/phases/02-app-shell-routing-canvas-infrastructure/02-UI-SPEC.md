## Layout & Composition

The shell is a fixed, non-scrolling frame with exactly three structural
regions plus two overlay layers — no responsive breakpoints (desktop-only
tool, per `REQUIREMENTS.md` Out of Scope):

```
┌─────────────────────────────────────────────────────────────────┐
│ [Logo/Mode▾] │ Top bar: carried-forward .seg / .tbtn / .search   │  <- 48px rail width,
├──────────────┼───────────────────────────────────────────────────┤     top bar height
│              │                                                    │     unchanged from
│  Mode rail   │                                                    │     Phase 1 toolbar
│  (icon-only, │            Canvas region (<Outlet/>)               │
│   per-mode   │        bridged LineageView / GraphView              │
│   items)     │                                                    │
│              │                              ┌──────────────────┐  │
│  ┄┄┄┄┄┄┄┄┄┄  │                              │ Inspector overlay │  │  <- floats over
│  Rail-bottom │                              │ (384px, floats,   │  │     canvas right
│  cluster     │                              │  never reflows    │  │     edge (D-10)
│  (⌘K, theme, │                              │  the canvas)      │  │
│  connection) │                              └──────────────────┘  │
└──────────────┴───────────────────────────────────────────────────┘
```

- **Rail** is `position: fixed`/flex, full viewport height, never scrolls
  with canvas content.
- **Canvas region** fills 100% of the remaining width/height (SHELL-02) —
  bridged `LineageView`/`GraphView` must size via flex/grid, never fixed
  pixel assumptions (Pitfall 3, D-15).
- **Inspector** is `position: absolute`/`fixed` relative to the canvas
  region's right edge, layered above it with elevation — it never
  participates in canvas layout flow (D-10). Its presence/absence causes
  zero reflow of the canvas beneath it.
- **Mode menu** (dropdown from the logo) and **command palette** are true
  overlays (Radix `DropdownMenu`/`Dialog`), positioned independent of the
  three structural regions.

### Overlay stacking order (new — not specified in Phase 1)

| Layer | z-index | Notes |
|-------|---------|-------|
| Rail + top bar chrome | `5` | Unchanged from the existing `.toolbar` value |
| Canvas content (`.card`, hover previews) | `6` | Unchanged from existing `GraphView` hover cards |
| Inspector overlay | `20` | Above canvas content, below all transient overlays |
| Rail tooltip (Radix Tooltip) | `50` | Above the inspector — a tooltip must never be occluded by it |
| Mode menu (Radix DropdownMenu) | `60` | Above tooltips — only one menu-class overlay is ever open at a time |
| Command palette (`cmdk` `Command.Dialog`) | `100` | Unchanged from the existing `.sp-overlay` value — topmost, blocks all other interaction while open |

## New Tier-3 Component Tokens

All values below resolve to a Phase-1 tier-2 semantic. Add these to
`components.css`'s existing tier-3 block (do not create a second block).

```css
/* Rail (SHELL-01, SHELL-02, D-01–D-05) */
--rail-width: 48px;                          /* = --space-12, per D-04 */
--rail-bg: var(--color-surface-1);           /* same tier as the toolbar */
--rail-border: var(--color-border);          /* right-edge divider from canvas */
--rail-item-size: 44px;                      /* touch-target exception, 01-UI-SPEC Spacing */
--rail-item-icon-size: 20px;
--rail-item-radius: var(--radius-control);
--rail-item-fg: var(--color-text-tertiary);
--rail-item-fg-hover: var(--color-text-secondary);
--rail-item-bg-hover: var(--color-surface-2);
--rail-item-fg-active: var(--color-accent);       /* current destination */
--rail-item-bg-active: var(--color-accent-dim);

/* Mode menu — app-logo dropdown (D-02) */
--mode-menu-bg: var(--color-surface-3);      /* topmost-overlay tier, per Elevation Model mapping */
--mode-menu-border: var(--color-border);
--mode-menu-shadow: var(--shadow-overlay);   /* dark theme: supplementary only, per Elevation Model */
--mode-menu-radius: var(--radius-card);
--mode-menu-item-radius: var(--radius-control);
--mode-menu-item-fg-active: var(--color-accent);

/* Inspector overlay (D-10, D-12, D-13) */
--inspector-width: 384px;                    /* literal component width, D-13's 360-400px range;
                                                 component geometry is a sanctioned exception to the
                                                 4px-multiple rule per components.css's own convention */
--inspector-bg: var(--color-surface-2);      /* one tier above --card-bg, so it visibly "floats"
                                                 over cards/nodes rather than reading as another card */
--inspector-border: var(--color-border);
--inspector-shadow: var(--shadow-overlay);   /* dark: supplementary only; light: primary elevation cue */

/* Command palette rebuild (D-17, NAV-01, NAV-03) */
--palette-width: min(640px, calc(100vw - 32px));  /* carried forward verbatim from search.css */
--palette-max-height: 60vh;                        /* carried forward verbatim from search.css */
--palette-bg: var(--color-surface-3);        /* upgraded from the old --card-bg (surface-1) to match
                                                 Elevation Model's explicit "command palette" -> surface-3
                                                 mapping — a deliberate, documented correction */
--palette-border: var(--color-border);
--palette-shadow: var(--shadow-overlay);

/* Rail-bottom cluster (D-05) */
--rail-bottom-gap: var(--space-2);
--theme-toggle-size: 44px;                   /* same touch-target rule as rail items */
--status-dot-size: 8px;                      /* connection status indicator, matches existing .tick size */
--status-dot-ok: var(--color-success);
--status-dot-off: var(--color-text-tertiary);
--status-dot-err: var(--color-destructive);
```

## Spacing Scale

Unchanged from Phase 1 — no new primitive spacing values this phase:

| Token | Value | Usage |
|-------|-------|-------|
| `space-1` | 4px | Icon gaps, inline padding |
| `space-2` | 8px | Compact element spacing |
| `space-3` | 12px | Default control padding |
| `space-4` | 16px | Default section/element spacing |
| `space-6` | 24px | Section padding |
| `space-8` | 32px | Layout gaps |
| `space-12` | 48px | Major section breaks — **also the rail width this phase (D-04)** |
| `space-16` | 64px | Page-level spacing |

**Exceptions (both inherited from Phase 1, both apply directly this phase):**

1. Icon-only interactive targets get a minimum **44×44px** hit target
   (rail items, rail-bottom cluster buttons, inspector close button,
   mode-menu trigger) — achieved via padding around a smaller (20px) glyph,
   never by inflating the visible rail width beyond 48px.
2. Fixed component widths (`--inspector-width: 384px`, `--palette-width`)
   are literals, not spacing-scale multiples — components.css's own
   documented convention (component geometry is exempt from the 4px-multiple
   discipline that governs padding/gap/margin).

## Typography

Unchanged ramp from Phase 1 — no new size/weight this phase. Template-required summary:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Label | 11px (`text-micro`) | 400 | 1.35 |
| Body | 13px (`text-base`) | 400 (600 for emphasis) | 1.45 |
| Heading | 18px (`text-heading`) | 600 | 1.3 |
| Display | 22px (`text-display`) | 600 | 1.25 |

**New usage this phase:** `text-display` (22px) was defined in Phase 1 "for
Phase 2's shell" but never consumed. It is consumed here for the first
time — the honest-placeholder page headline (Push, Data Products) is a
genuine page-level title with no card/panel context around it, unlike every
other heading in the app so far (which sits inside a card/inspector at
`text-heading`, 18px). Do not use `text-display` for the inspector title,
mode-menu label, or rail tooltips — those stay at `text-heading` or
`text-micro` per their existing roles.

## Color

Unchanged 60/30/10 split from Phase 1 — no new hue, no new primitive this phase:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--color-surface-canvas` | Canvas background (bridged LineageView/GraphView, unchanged) |
| Secondary (30%) | `--color-surface-1` / `--color-surface-2` / `--color-surface-3` | Rail (`surface-1`), inspector (`surface-2`), mode-menu/palette/tooltip (`surface-3`) — see Component Tokens above for the exact per-component tier assignment introduced this phase |
| Accent (10%) | `--color-accent` | Reserved for, **added this phase**: active/current rail item (icon + `--rail-item-bg-active` wash), current-mode checkmark in the mode menu, command-palette selected row (`--color-accent-dim`, carried forward from `.sp-row[data-selected]`), inspector close/focus rings, theme-toggle active state. Unchanged from Phase 1: traced/hover state on both canvases, primary CTA buttons, active segmented-control indicator |
| Destructive | `--color-destructive` | **Not consumed this phase.** No destructive action ships until Phase 5 (Push placeholder is a read-only honest-placeholder page, not a live write surface) |

Accent is never used for: rail item default/hover state (uses
`--rail-item-fg`/`--rail-item-fg-hover`, not accent, so the *current*
destination stays the only accent-colored rail item — a hover preview must
not visually compete with the actual selection), domain identity, or
edge-type identity (unchanged per-canvas colour rule, Phase 1).

**Non-blocking notice styling (D-09):** the "couldn't resolve segment"
notice reuses the existing `.src-chip` pattern verbatim (Bronze domain
color, 12% wash background, pill radius) — the same visual language already
used for "sample data" / "catalog unavailable" in the current top bar. This
is a deliberate reuse, not a new color: it signals "informational, not
blocking, not destructive," which is exactly what Bronze's existing usage
already means in this app. It is explicitly **not** `--color-destructive` —
an unresolved URL segment falling back to its nearest ancestor is a handled,
recoverable case, not an error.

### Covered — states Phase 2 actually introduces

| Category | Element(s) | Status | Resolution |
|----------|------------|--------|------------|
| loading | Canvas region during the root loader's `fetchGraph()` | ✅ covered | Rail/mode-menu/top-bar chrome render immediately (they don't depend on graph data); only the canvas region shows a pending state via TanStack Router's route `pendingComponent` — a subtle skeleton, not a full-page blocker, since the shell around it is already interactive |
| error | Unresolved URL path segment (D-09) | ✅ covered | Redirects to nearest resolvable ancestor with `replace: true`; renders the Copywriting Contract's exact notice copy as a dismissible `.src-chip`-styled banner. See Pitfall 4 in `02-RESEARCH.md` for the redirect-loop guard this depends on |

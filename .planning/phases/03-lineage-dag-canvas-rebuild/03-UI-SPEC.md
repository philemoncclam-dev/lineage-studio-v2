## Layout & Composition

The lineage mode's canvas region (inside `shell-canvas`, per `02-UI-SPEC.md`'s
three-region shell) gains one new internal structural element this phase — a
slim toolbar strip — and replaces the SVG canvas with an xyflow canvas:

```
┌─────────────────────────────────────────────────────────────────┐
│ Rail (unchanged)  │  lineage-toolbar: [Table|Column seg] ⋯ Refreshed 3m ago │  <- new, this phase
│                    ├───────────────────────────────────────────────┤
│                    │                                                │
│                    │   xyflow canvas: dagre LR layout,              │
│                    │   dot-grid background, table/notebook cards    │
│                    │                                                │
│                    │                              ┌──────────────┐  │
│                    │                              │  Inspector   │  │  <- unchanged
│                    │                              │  (384px)     │  │     Phase 2 overlay
│                    │                              └──────────────┘  │
└────────────────────┴───────────────────────────────────────────────┘
```

**Why a new toolbar strip, not the rail:** Phase 2's rail is icon-only, 44px
touch targets, tooltip-labelled (`02-UI-SPEC.md` Icon library note) — it has
no room for a labelled segmented control or a readable timestamp string, and
Phase 2 never actually built a shared top-bar region (the ASCII diagram in
`02-UI-SPEC.md` was aspirational; `AppShell.tsx` renders only
`shell-rail-col` + `shell-canvas`, confirmed by reading the file this
session). The lineage-mode toolbar strip is therefore **owned by this
phase's canvas component**, mounted at the top of `shell-canvas`'s content
above the xyflow canvas — not a rail item, not a persistent legend (the
per-canvas-colour-rule and the "no persistent legends" dislike both stay
intact; this strip carries controls and status text, not a colour key).

- **`lineage-toolbar`**: height auto (content-driven), `--spacing-2`
  vertical / `--spacing-4` horizontal padding, `--color-surface-1` bg (same
  tier as the historical `.toolbar`), `--color-border` bottom edge. Reuses
  the exact `.seg`/`.seg button.on` treatment verbatim (SHELL-04's
  explicitly-liked pattern) for the table↔column toggle — no new control
  chrome invented.
- **xyflow canvas region**: fills all remaining height/width below the
  toolbar strip, `flex: 1; min-height: 0`. Background: xyflow's own
  `<Background variant="dots" />`, `gap={22}` `size={1.2}`
  `color="var(--color-grid-dot)"` — the exact dot-grid parameters the old
  `.ls-canvas`/`.gv-canvas` radial-gradient already used, now expressed via
  xyflow's native background component instead of a CSS trick.
- **No minimap** (`showMinimap` never set) — explicit Out-of-Scope item,
  standing dislike.
- **Inspector**: unchanged Phase 2 contract — `position: absolute` over the
  canvas's right edge, 384px, `--color-surface-2`, never reflows canvas
  content. This phase only adds new *content* inside it for column
  selections (see Inspector Column-Detail Layout below); the shell/overlay
  mechanics are untouched.

## xyflow Node/Edge Architecture (DAG-01, DAG-02, DAG-07)

### Node types

| xyflow node type | Renders | Used for |
|---|---|---|
| `tableNode` | Card: header (domain tick + name + layer sub-label) + column rows (when the global toggle is Column) or nothing below the header (when Table) | Every `table` node in `AppModel.tables` |
| `notebookNode` | Card: header only (domain tick=`--color-domain-notebook` + name + `"notebook · PySpark"` sub-label), never expandable | Every `notebook` node in `AppModel.notebooks` |

Both node types are thin wrappers around the **existing visual language**
(`.ls-node`/`.tick`/`.title`/`.sub`/`.col` classes in `components.css`) —
this phase ports that CSS to xyflow's node-component contract, it does not
redesign the card's look.

### Node geometry (dagre inputs — must be exact, dagre needs real dimensions)

| Token | Value | Note |
|---|---|---|
| `--dag-node-width` | **240px** | Up from the old SVG view's 208px — the extra 32px is spent on the wider column-name + type + PK-pill row now that rows render as real xyflow DOM content (not manually measured via `getBoundingClientRect`). Fixed literal; component geometry is the sanctioned exception to the 4px-multiple rule, and 240 is itself a clean multiple of 8 |
| `--dag-node-header-height` | **40px** | `--spacing-2` (8px) vertical padding × 2 + `text-base` (13px/1.45 ≈ 19px) line height, rounded to a clean 40 |
| `--dag-node-row-height` | **28px** (= `--row-height`, reused verbatim — locked Phase-1 density primitive) | Every column row, expanded mode only |
| `--dag-node-max-height` | **320px** | = header (40) + 10 × row-height (280). Caps an expanded card at 10 visible rows; wider tables **scroll inside the card** past that (D-04) — `overflow-y: auto` on the column-list container, no virtualization, no truncate-with-count (explicit v1 scope) |
| Collapsed (Table-level) node height | **40px** (header only, uniform for every table) | D-03: global toggle, headers-only when off |
| Expanded (Column-level) node height | `40 + min(columns.length, 10) × 28`, capped at 320 | Computed once per render pass, fed to dagre as that node's `height` |
| Notebook node height | **40px**, always (never expandable — notebooks have no column rows) | |

### Dagre tuning

```
dagre.layout(graph, {
  rankdir: 'LR',       // DAG-01: left-to-right
  ranksep: 64,          // --spacing-16 — gap BETWEEN rank columns (the
                         // "column-to-column gap" 01-UI-SPEC.md's spacing
                         // table already names this token's job as)
  nodesep: 32,           // --spacing-8 — vertical gap between cards stacked
                         // in the same rank
  edgesep: 16,           // --spacing-4 — default dagre-recommended edge
                         // channel spacing, unchanged from dagre's default
  marginx: 32,           // --spacing-8 — outer canvas padding, so xyflow's
                         // fitView can use padding: 0 (dagre already
                         // reserves the margin; don't double-pad)
  marginy: 32,
})
```

**Determinism (DAG-07):** dagre's rank assignment is a pure function of the
graph's edge topology; node widths/heights above are themselves a pure
function of `(table.columns.length, globalToggleState)`. The same
`LineageGraph` + the same toggle state therefore always produces the same
`(x, y)` for every node — no random seed, no incremental/warm-start
behaviour (that's Phase 4's force-directed graph, not this deterministic
layered DAG). Re-running layout on toggle flip is expected and correct: it
is still deterministic for that toggle state, not a "re-jump."

### Column-row edge anchoring (DAG-02 — the core correctness requirement)

Each column row renders two invisible xyflow `<Handle>` elements, absolutely
positioned via CSS at the row's exact vertical center — replacing the old
SVG view's manual `getBoundingClientRect()`-based `anchor()`/measure-on-tick
approach entirely (a real simplification this rebuild buys, not just a
migration):

```
top:    id={`${col.key}__target`}, position={Position.Left},
        style={{ top: headerHeight + rowIndex * rowHeight + rowHeight / 2 }}
right:  id={`${col.key}__source`}, position={Position.Right},
        style={{ top: headerHeight + rowIndex * rowHeight + rowHeight / 2 }}
```

- **Expanded (Column) mode:** every column edge's `sourceHandle`/
  `targetHandle` references the exact `${col.key}__source` / `${col.key}
  __target` id — edges connect to the precise row, not the node boundary
  (this is the literal DAG-02 requirement).
- **Collapsed (Table) mode:** column handles are not rendered (no column
  rows exist in the DOM). Every `tableNode`/`notebookNode` additionally
  renders one always-present fallback handle pair, `__node__source` /
  `__node__target`, at the header's vertical center. Column edges' handle
  ids are switched to the fallback pair when the global toggle is Table —
  a pure function of `(edge, toggleState)`, recomputed on toggle exactly
  like node geometry above, keeping DAG-07 determinism intact across the
  toggle.
- **Object-level edges** (notebook reads/writes another table, the existing
  `ops` array) always use the `__node__*` fallback pair on both ends —
  notebooks never have column rows to anchor to.

### Edge rendering

One custom edge component (`lineageEdge`) handles both column-level and
object-level edges — same visual family as the old view's cubic bezier
(`curve()` in the retired `LineageView.tsx`), reimplemented as an xyflow
`getBezierPath`-style custom edge so it still clears intervening cards the
way dagre's rank spacing already accounts for. No new edge shape is
invented; this is a straight port of the existing, already-approved curve.

## Provenance & Edge-Type Channel (TRUST-01)

Two fully independent visual channels on every edge, per the locked
Phase-1 per-canvas colour rule and D-08:

| Channel | Values | CSS mechanism |
|---|---|---|
| **Edge type** (hue — unchanged Phase-1 channel) | reads / writes / derives | `stroke: var(--color-edge-reads/writes/derives)` |
| **Provenance** (line style — new this phase, D-08) | declared / inferred | `stroke-dasharray: none` (declared, solid) vs `stroke-dasharray: 5 4` (inferred, dashed) — the literal `5 4` value is carried forward unchanged from the current codebase's existing dash pattern |

**Phase-3 reality (D-09/D-10):** every edge this phase renders is
`data-provenance="inferred"` — 100% dashed. The `declared`/solid style is
fully built (both dagre-independent CSS rules exist and are exercised by
tests) but has **no live data path to trigger it yet**; Phase 5's
Purview read-back is what starts producing `declared` edges. No provenance
enum is added to the backend model this phase (D-10) — the frontend simply
hardcodes `provenance: 'inferred'` on every edge it renders until Phase 5.

**No persistent provenance legend on this canvas.** Unlike the Knowledge
Graph's one explicitly-wanted domain legend (GRAPH-06), the DAG canvas gets
no always-visible dashed/solid key — that would be exactly the disliked
"persistent legend" pattern (Out-of-Scope table). Provenance is discoverable
two ways instead, both contextual, neither persistent:

1. **On hover/focus of any edge**, a native tooltip (`<title>` inside the
   edge's SVG group, or `aria-label` read by AT on focus) states:
   `"{kind} edge (inferred) — {sourceLabel} → {targetLabel}"`.
2. **On selection of a column**, the Inspector shows the provenance
   explicitly as text + a small inline swatch icon (see Inspector layout
   below) — this is the TRUST-02 detail surface, not a canvas-chrome legend.

## Trace & Selection Interaction Contract (DAG-03, DAG-04, D-05, D-06, D-07)

**One trace treatment, one opacity value — no third tier.** D-05's heading
("one trace treatment") is read literally: exactly two visual states exist
for every node, column row, and edge while a trace is active — **traced
(opacity 1.0, full interactivity)** or **unrelated (opacity 0.15,
non-interactive to the mouse)**. No intermediate "partially related" opacity
is introduced.

| Element | Traced state | Unrelated state |
|---|---|---|
| Column row (the exact hovered/selected column) | `--color-accent-dim` background wash + `box-shadow: inset 2.5px 0 0 var(--color-accent)` (carries forward `.col.sel` verbatim) | n/a — this is always the traced set's anchor |
| Column row (upstream/downstream of the active column, i.e. traced but not the anchor) | `--color-accent-dim` background wash only, no inset bar (carries forward `.col.hot` verbatim) | opacity `0.15`, `pointer-events: none` |
| Card (contains ≥1 traced column, or is an object-level trace endpoint) | Header/border stay at opacity `1.0` — the card's *chrome* is never dimmed just because some of its rows are unrelated | n/a |
| Card (contains zero traced columns and is not a trace endpoint) | n/a | Whole card (header + border + all rows) dims to `0.15` as one unit, `pointer-events: none` |
| Edge (part of the traced path) | `stroke: var(--color-accent)`, `stroke-width: 2.5px` (up from the base `1.5px`), `opacity: 1.0` | n/a |
| Edge (not part of the traced path) | n/a | `opacity: 0.15`, `pointer-events: none` |

**Transitions:** `opacity 180ms, stroke-width 180ms` — the exact duration
already in production (`.ls-edges .edge` in `components.css`), default
ease, no spring/scale/transform. This is a deliberate, minimal carry-forward
— Phase 7 (MOT-01/02) owns real motion design; this phase's transitions
exist only so dim/undim doesn't hard-cut, nothing more.

**Hover vs. click (D-06):** hovering a column computes and shows a trace
transiently (same opacity/colour rules above); moving the mouse off ends
the hover trace immediately. Clicking a column calls `useSelection().select()`
(Phase 2's existing `?sel`/`?col` store, D-07) — the resulting persistent
selection renders with the **identical visual treatment** as a hover trace
(no separate "selected" look). If the user hovers a *different* column
while one is already selected, that hover's trace transiently overrides the
rendered trace (without touching the URL/selection state); when the hover
ends, rendering reverts to the persisted selection's trace. Selection clears
via Esc, the Inspector close button, or an empty-canvas click — all three
already wired at the shell level (Phase 2's `Inspector.tsx` Esc listener,
carried forward unchanged) plus the canvas's own empty-click handler
(ported from the retired `LineageView.tsx`'s existing `onClick` guard).

**Mouse-non-interactive vs. keyboard-reachable — explicit adjudication.**
D-05 says unrelated elements "become non-interactive"; DAG-08/pitfall #19
require every node and edge stay keyboard-reachable regardless of trace
state. These are reconciled, not in conflict: `pointer-events: none` above
applies to **mouse/pointer input only**. `tabIndex`, `aria-*` attributes,
and focus-visible styling are **never removed** from a dimmed element — a
keyboard user tabbing through the graph can still land on and select an
element the mouse currently can't reach mid-trace. This is the one place
this document deliberately diverges from a literal reading of "non-
interactive" to keep DAG-08 satisfied.

## Keyboard & Assistive Technology Traversal Model (DAG-08, SC#6, pitfall #19)

Designed to be dual-purpose: the same scheme that makes the canvas fully
operable without a mouse is also the fastest way for a sighted power user to
walk a lineage path without touching the trackpad.

### Focus architecture: roving tabindex over a flat node+row list

The canvas region is **one Tab stop** from the surrounding chrome (roving
tabindex pattern, same class of pattern as a toolbar or listbox) —
`role="group"` `aria-label="Lineage graph: {N} tables, {N} notebooks,
{N} connections"` on the xyflow wrapper. Tabbing *into* the canvas focuses
the first focusable element in reading order (leftmost rank, topmost card).
Once inside:

| Key | Action |
|---|---|
| `Tab` / `Shift+Tab` | Leaves the canvas entirely (to the toolbar strip / Inspector / rail) — the canvas never traps focus |
| `↓` / `↑` | Move focus to the next/previous column row within the current card; at the last/first row, moves to the next/previous card in the same rank |
| `→` / `←` (on a **card header**, e.g. a notebook or a collapsed table) | Move focus to the next/previous rank (dagre depth column) — column-by-column traversal matching the DAG's own left-to-right structure |
| `→` (on a **column row that has an active trace**, i.e. is currently hovered/focused with a live downstream connection) | **Path-walk**: jumps focus directly to the first downstream connected column, skipping intermediate unrelated rows/cards — the power-user "walk the edge" affordance that dual-purposes as DAG-08's edge-operability requirement (see note below) |
| `←` (symmetric) | Path-walk to the first **upstream** connected column |
| `Enter` / `Space` on a column row | Equivalent to a click — freezes the trace as the persistent selection (`select()`), same as D-06 |
| `Enter` / `Space` on a card header | Selects the table/notebook itself (`select(nodeId)`, no `col`) — gives keyboard users the same table-level Inspector access the command palette already provides, with no separate affordance needed |
| `Esc` | Clears selection (existing Phase-2 shell-level Esc listener, unchanged — this phase adds no second Esc handler) |
| `Home` / `End` | Jump to the first/last focusable element in the whole canvas (first notebook or table in rank 0 / last node in the deepest rank) |

**Edges are not independently tabbable.** DAG-08/SC#6 requires every
mouse-reachable node *and edge* be keyboard-reachable and carry semantic
labelling — resolved without making dozens-to-hundreds of edges separate
tab stops (which would make Tab traversal impractical on any real graph):
the `→`/`←` path-walk keys above give a keyboard user the exact experience
of "traversing an edge" (focus moves from a column to the column it feeds,
which *is* what an edge represents) without the edge needing its own DOM
focus target. Semantic labelling for edges is satisfied instead by:

1. The hover/focus tooltip on every edge (Provenance section above) —
   reachable because path-walking focuses the *columns* an edge connects,
   and the connecting edge's tooltip is announced via `aria-describedby`
   pointing from the destination column back to the edge's label.
2. A visually-hidden (`sr-only`, not `display:none` — must stay in the
   accessibility tree) summary list enumerating every edge in the current
   graph in reading order: `"{sourceCol} → {targetCol}, {kind}, {provenance}
   via {notebook}"` per line. This mirrors the same "accessible text
   alternative to the visual graph" pattern GRAPH-09 requires for the
   Knowledge Graph, applied here even though DAG-08 doesn't use that exact
   phrase — it is the concrete implementation of "carries semantic
   labelling for assistive technology" for edges specifically.

### Focus-visible treatment

`:focus-visible` only (never on stray mouse-click residual focus) —
`box-shadow: 0 0 0 3px var(--color-accent-dim)` + `border-color:
var(--color-accent)`, the exact ring already established by `.ls-node.focus`
/`.tcard.focus` in `components.css`. Column rows get the same ring at a
tighter radius (`--radius-input`, 5px) since a row is a smaller target than
a card.

### Accessible names

| Element | `aria-label` template |
|---|---|
| Canvas wrapper | `"Lineage graph: {N} tables, {N} notebooks, {N} connections"` |
| Table card header | `"{name}, {layer} table, {N} columns"` |
| Notebook card header | `"{name}, notebook"` |
| Column row | `"{name}, {type}{, primary key if pk}, {table name}"` |
| Table↔Column toggle segmented control | `"Lineage detail level"` (group), `"Show table-level detail"` / `"Show column-level detail"` (per button) |
| Last-refreshed indicator | `"Lineage data {refreshed {relative time} ago | showing bundled sample data}"` — full sentence, not an abbreviation, since it has no visible label beside it (see Freshness Indicator below) |

## Inspector Column-Detail Layout (DAG-05, TRUST-02, D-11, D-12, D-13)

New content inside the unchanged Phase-2 384px overlay, rendered when
`useSelection().col` is set (column selected) — extends `Inspector.tsx`'s
existing `resolveSelected()`/`TableCard` pattern with a `ColumnCard`, in the
same header + `.sec`-per-section shape already established:

```
┌─────────────────────────────────────┐
│ column                          [×]  │  <- inspector-kind / inspector-close, unchanged
│ {column_name}                        │  <- inspector-title, unchanged text-heading
│ ┄┄┄ Inferred                         │  <- NEW: provenance swatch + label, text-micro
├─────────────────────────────────────┤
│ TRANSFORM                            │  <- .sec-t, unchanged treatment
│ ┌───────────────────────────────┐   │
│ │ upper(customer_name)           │   │  <- .xform code, mono, existing class
│ └───────────────────────────────┘   │
│ Computed as upper(customer_name)     │  <- .xform p, existing class
│ in clean_customers.                  │
├─────────────────────────────────────┤
│ SOURCE → TARGET                      │  <- .sec-t
│ ↑ raw_customers.customer_name        │  <- .flow-item, existing class, clickable
│ ↓ silver_customers.customer_name     │     (this column itself, shown for symmetry)
├─────────────────────────────────────┤
│ EVIDENCE                             │  <- NEW section
│ Matched in clean_customers,          │  <- text-micro, text-secondary
│ cell 3, line 12:                     │
│ ┌───────────────────────────────┐   │
│ │ SELECT UPPER(customer_name)    │   │  <- mono code block, same .xform code
│ │ AS customer_name FROM ...      │   │     treatment reused verbatim
│ └───────────────────────────────┘   │
│ Inferred from static pattern-        │  <- text-micro, text-tertiary, italic-free
│ matching — not executed.             │     (D-13: never overstate certainty)
├─────────────────────────────────────┤
│ CONNECTIONS                          │  <- .sec-t, reused pattern from TableCard
│ Upstream 1 · Downstream 1            │
└─────────────────────────────────────┘
```

**Section order and rationale:**

1. **Provenance line** directly under the title (not its own `.sec`) —
   contextual, not a canvas legend; always visible the instant a column is
   selected, no scrolling needed. Swatch: a 10px inline SVG line,
   `stroke-dasharray: 5 4` when inferred / none when declared,
   `stroke: var(--color-text-tertiary)` (neutral — provenance is a shape
   channel, not a colour channel, so its own UI chrome stays achromatic to
   avoid implying a colour meaning that doesn't exist).
2. **Transform** — reuses the already-defined-but-previously-unused
   `.xform`/`.xform code`/`.xform p` classes verbatim. `code` = the
   transform expression (`m.transform`), `p` = the frontend-synthesized
   plain-English sentence already produced by `adapt.ts`'s `xform` map
   (D-13: no new synthesis logic, just consumed here for the first time).
   When `m.transform` is null (pass-through, no transform), the code block
   is omitted and only the plain-English sentence renders — mirrors
   `adapt.ts`'s existing "Passed through from…" branch.
3. **Source → Target** — reuses the already-defined-but-previously-unused
   `.flow`/`.flow-item` classes verbatim. One row per resolved source
   column (↑, upstream) and the column itself (↓, downstream/target),
   using `.flow-item .dir` (existing chevron icon) to indicate direction.
   Each row is clickable → calls `select()` with that column's ids,
   letting the Inspector double as a lineage-walking tool (mirrors the
   keyboard path-walk affordance above, mouse equivalent).
4. **Evidence** — the new section this phase's scope adds (D-11/D-12).
   Header line states notebook + cell index + line number as plain text
   (`text-micro`, `--color-text-secondary`); the verbatim matched snippet
   renders in the same mono code-block treatment as Transform's `.xform
   code` (visual consistency — both are "raw evidence" blocks, not prose).
   The closing caption — **"Inferred from static pattern-matching — not
   executed."** — is locked copy (see Copywriting Contract) and is the
   direct fix for pitfall #6: it never lets the evidence read as more
   authoritative than a regex match actually is.
5. **Connections** — reuses `TableCard`'s existing `.sec`/`.sec-t` pattern,
   repurposed for a column: `"Upstream {N} · Downstream {N}"` counts the
   traced set's size in each direction (from the same `trace()` walk the
   canvas itself already computes for hover/selection).

**Missing-evidence fallback:** if a selected column has no resolvable
Evidence (edge case — e.g. a column reached via a pass-through with no
identifiable source expression), the Evidence section is omitted entirely,
same "missing field omits its row" rule Phase 2's Inspector already applies
(`02-UI-SPEC.md` partial-state resolution) — never a rendered-blank block.

### Backend evidence threading (D-12 — scoped, additive backend change)

`ColumnMap` (`backend/app/models.py`) gains one new **optional** field:

```python
class ColumnMap(BaseModel):
    from_column: str
    to_column: str
    transform: str | None = None
    evidence: ColumnMapEvidence | None = None   # NEW, additive, optional

class ColumnMapEvidence(BaseModel):
    notebook: str
    cell_index: int
    line: int
    snippet: str
```

`parser.py`'s `_column_maps(cell)` already has everything needed to
populate this: the matched `SELECT` statement's `re.Match` object exposes
`.start()`, from which `cell[:m.start()].count('\n')` gives the line
number, and the enclosing `for cell in nb.cells` loop already has the cell
index via `enumerate()`. The snippet is the matched SELECT clause's raw
text (`m.group(0)`, trimmed). **`LineageGraph` stays backward-compatible**
per CLAUDE.md's stability rule — `evidence` is optional on both the
Pydantic model and the frontend's `ColumnMap` TypeScript interface in
`api.ts`; existing manual-JSON-upload payloads with no evidence field
continue to parse and render (Evidence section omitted, per the fallback
above).

## Freshness Indicator (TRUST-03, D-14) & Table↔Column Toggle (DAG-06, D-03)

Both live in the new `lineage-toolbar` strip (Layout & Composition, above):

```
[ Table | Column ]                                    ┄┄┄ Refreshed 3m ago
  ^ segmented control, left                             ^ freshness text, right
```

### Table↔Column toggle

- Reuses `.seg`/`.seg button.on` verbatim (SHELL-04's carried-forward,
  explicitly-liked treatment) — two buttons, "Table" / "Column".
- **Default: "Column" active** (D-03: expanded by default).
- **Global, not per-card** — flips every card's rendered mode
  simultaneously (D-03: "no per-card expand/collapse state in v1"). Table
  headers are therefore **not independently clickable to toggle** anymore
  — the old `LineageView.tsx`'s `onClick={() => toggle(t.id)}` on the card
  head is retired; a header click now only selects the table (per the
  Enter/Space behaviour in the Keyboard section).
- State lives as local component state in the lineage view (not the URL) —
  it is a display-density preference, not addressable/shareable selection
  state, so it does not join `?sel`/`?col` in the URL (consistent with
  Phase 2's D-07 selection-store scope, which owns *what's selected*, not
  *how dense the canvas renders*).

### Freshness indicator

- **Copy:** `"Refreshed {relative}"` (e.g. `"Refreshed 3m ago"`, using
  `Intl.RelativeTimeFormat`), `title` attribute = the absolute ISO
  timestamp for a hover tooltip with the precise value.
- **Fallback (new finding this session):** `AppModel.source` already
  distinguishes `'live'` (real `fetchGraph()` data) from `'sample'`
  (bundled demo data, silently substituted by `routes/__root.tsx`'s
  `fetchGraph().catch(() => null)` fallback when the backend is
  unreachable). When `source === 'sample'`, the indicator reads
  **"Showing bundled sample data"** instead of a relative timestamp — a
  real refresh time would be misleading/fabricated for data that was never
  actually fetched. This distinction did not exist anywhere in the app
  before this phase and is this phase's concrete fulfillment of TRUST-03
  ("shows when lineage data was last refreshed" implicitly includes
  "shows when it *isn't* real fetched data").
- **Source, no new persistence (D-14):** the root loader
  (`routes/__root.tsx`) captures `fetchedAt: Date.now()` alongside `graph`
  the moment `fetchGraph()` resolves successfully, and passes it through
  `RouterContext` the same way `graph` already flows — an in-memory value
  for the current session only, never written to storage.
- Styling: `text-micro`, `--color-text-tertiary`, a small 14px clock-icon
  SVG (same inline-stroke convention) preceding the text, right-aligned in
  the toolbar strip.
